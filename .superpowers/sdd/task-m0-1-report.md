### 2. CameraCapture module

**`CameraConfiguration.swift`** — Pure immutable struct (`Sendable`, `Equatable`).
- `preset: AVCaptureSession.Preset` and `targetFPS: Int`
- FPS clamped to `[minimumFPS=1, maximumFPS=60]` in the initialiser; no magic numbers inline
- `defaultConfiguration`: `.hd1280x720` at 30 fps

**`CameraFrameDelegate.swift`** — Protocol with two `nonisolated` methods:
- `didOutputPixelBuffer(_:timestamp:)` — called on the dedicated frame queue
- `didChangeState(_:)` — always dispatched to the main queue before delivery

**`CameraCapture.swift`** — `final class`, `@unchecked Sendable`, ~200 lines across two responsibilities (core class + file-private helpers).

Thread-safety model:
- `OSAllocatedUnfairLock<CaptureState>` for lock-free state reads from any thread
- `NSLock`-protected `DelegateBox` for the weak delegate reference
- `nonisolated(unsafe)` + `sessionQueue`-exclusive access for all AVFoundation objects
- Dedicated `frameQueue` (`com.picpal.camera.frames`) for sample buffer delivery
- `sessionQueue` (`com.picpal.camera.session`) serialises all session lifecycle operations
- `SampleBufferReceiver` — internal `NSObject` bridge (AVFoundation delegate → Swift closure), avoids forcing `CameraCapture` into an ObjC protocol

Public API:
```swift
var captureState: CaptureState      // thread-safe read
var currentConfiguration: CameraConfiguration
weak var delegate: (any CameraFrameDelegate)?

func configure(preset: AVCaptureSession.Preset, fps: Int)
func requestPermissionAndStart()
func stop()
```

Permission flow:
- `.authorized` → starts session immediately
- `.notDetermined` → requests access; denied → `.permissionDenied` state
- `.denied` / `.restricted` → appropriate state without crashing

## Design decisions

1. **`@unchecked Sendable` + `nonisolated(unsafe)` + locks** over actor: AVFoundation delegate callbacks are Obj-C and can't be dispatched to a Swift actor directly. The explicit queue/lock model matches Apple's recommended AVFoundation pattern and is idiomatic for Swift 6 + AVFoundation integration.

2. **`SampleBufferReceiver` bridge class**: keeps `CameraCapture` from conforming to an Obj-C protocol, makes the closure capture chain explicit and `@Sendable`, and avoids `@objc` on the main class.

3. **FPS clamping in `CameraConfiguration.init`** (not in `configure()`): lets the struct be unit-tested independently of async session logic.

4. **State notifications on main queue**: state-change callbacks always arrive on the main queue regardless of which internal queue triggered the transition, making it safe for `@MainActor` UI code to consume.

## Concerns / follow-up for later tasks

- `applyFrameRate` silently skips if the device's active format doesn't support the requested FPS (logs nothing). M0-4 (telemetry) should surface actual vs. requested FPS.
- The camera always uses `.builtInWideAngleCamera` / `.back`. Front camera support can be added to `CameraConfiguration` when a ticket calls for it (YAGNI for now).
- `SampleBufferReceiver` does not implement `captureOutput(_:didDrop:from:)`. Dropped-frame counting belongs in M0-4.
