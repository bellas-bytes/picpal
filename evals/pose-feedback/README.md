# Pose feedback replay

The checked-in real manifest is deliberately empty. No licensed participant images, annotations, baseline accuracy, or physical-device results are supplied. Numeric Swift tests and the synthetic labels inside `evaluate.test.mjs` test software contracts only; they are not detector accuracy evidence.

## Collect and label privately

Proposed diagnostic pilot: 100 reference/live pairs and 20 short correction clips from at least 10 consenting participants. Obtain explicit local-evaluation rights for every reference and live asset; keep consent records, identifying information and pixels outside the repository. No tool uploads these assets. Consent for evaluation does not grant training rights.

Cover glasses, sleeves, varied skin tones/light/backgrounds, either hand, two hands, portrait and both landscape directions, cropped fingers, missing wrists, background faces, near-mouth occlusion, already-correct poses and unassessable details. Use two independent held-out annotators and adjudicate disagreements. Label acceptable **final coordinator action IDs** from the replay (multiple allowed; selfie IDs retain stable detail/direction IDs such as `selfie_hand_position_up`; non-selfie IDs may be normalized differently from diagnostic `localActionID`), forbidden actions, unknown details and completed details at each sampled timestamp. Completion labels describe what is true at that frame, including sustained completion; repeated frozen or stale evidence must not create a new completion. Keep the previously debugged peace-sign example in development.

Assign splits before calibration. Connected participant, session and reference-family components must stay in one split, including adjacent frames and transformed copies. The validator checks transitive leakage. `rightsRecords` entries point to private consent/license records and assert `localEvaluation: true`. It does not independently establish legal permission.

Each record contains the fields documented in `manifest.schema.json`. `frames` is the exhaustive scoring denominator, not a list of outputs to keep. Frame timestamps must increase. Detail labels use `hand_position`, `head_tilt`, `head_turn`, `finger_spread`, `hand_roll`, `shoulder_tilt`, `gesture`, or `palm_direction`; the latter two are label-only and not focus choices. The native focus selector supports the first six. Optional `selfieAtMinimumZoom: true` must be labeled from actual camera limits; zoom 1 alone does not imply the hardware minimum.

Images and clips must contain the upright **displayed** pixels. Image EXIF orientation and video preferred-track transforms are baked once by the replay loader. `mirrored` records whether those pixels are mirrored; it does not request another flip. Reference and live geometry use the same aspect-based viewport. This offline harness does not reproduce every production preview crop, video tracker state, camera queue or rendered UI delay. Export distinct transformed cases to evaluate orientation/mirroring.

## Validate, replay, score

```sh
node --test evals/pose-feedback/evaluate.test.mjs
node evals/pose-feedback/evaluate.mjs --manifest /private/data/manifest.json --asset-root /private/data --validate-only
```

Validate before native replay: it checks rights linkage, labels, splits, private-root containment and symlink escapes. Do not store raw assets or private manifests in this directory.

Regenerate the project with `xcodegen generate`. Run the `PicPal` scheme on the locally discovered simulator with only `PicPalTests/PoseFeedbackReplayTests`. Pass these environment variables to the **test process** (for `xcodebuild`, prefix each with `TEST_RUNNER_`):

- `POSE_REPLAY_MANIFEST`: absolute validated private manifest path.
- `POSE_REPLAY_ASSET_ROOT`: absolute private dataset root accessible to the test process.
- `POSE_REPLAY_OUTPUT`: writable absolute JSONL output path.
- `POSE_REPLAY_REVISION`: exact app git revision (include dirty status when applicable).

Example invocation, after substituting a real simulator ID and private paths:

```sh
TEST_RUNNER_POSE_REPLAY_MANIFEST=/private/data/manifest.json \
TEST_RUNNER_POSE_REPLAY_ASSET_ROOT=/private/data \
TEST_RUNNER_POSE_REPLAY_OUTPUT=/private/tmp/pose-baseline.jsonl \
TEST_RUNNER_POSE_REPLAY_REVISION=REVISION \
xcodebuild test -project PicPal.xcodeproj -scheme PicPal \
  -destination 'platform=iOS Simulator,id=SIMULATOR_ID' \
  -only-testing:PicPalTests/PoseFeedbackReplayTests
node evals/pose-feedback/evaluate.mjs --manifest /private/data/manifest.json \
  --decisions /private/tmp/pose-baseline.jsonl --output /private/tmp/pose-baseline-report.json --require-gates
```

Check the actual project path generated by the repository configuration. A normal test run without the manifest environment variable returns without replay and is **not** evidence that the dataset ran. Configured empty manifests fail. Physical devices need assets staged into their accessible sandbox; host paths alone are insufficient.

The replay calls the production Vision hand adapter, MediaPipe body tracker (image mode), local comparator and cue coordinator. It exports requested and actual clip timestamps, app revision, OS/device, detector configuration, capture metadata, raw action ID/caption, confidence provenance, evidence availability and detector-to-decision processing time. Face/person association is production logic. This is a local-only offline replay; exported latency is not measurement-to-visible-cue latency. Real-time video tracking and camera invalidation need separate app/device tests.

JSONL contains one row per labeled frame: `id`, `timestamp`, nullable `action` and `detail`, `completedDetails`, boolean `allowsAutoCapture` and `referenceMatched`, plus provenance. Missing, unexpected and duplicate rows cannot disappear. Abstention lowers coverage; unknown-detail cues, forbidden directions, unsupported completion and any full-match/capture in this partial-selfie benchmark fail. Precision counts acceptable emitted actions; coverage counts emitted cues on assessable labeled frames, so inspect precision alongside it. Participant counts are exported; participant-bootstrap uncertainty and temporal reversal/delay review remain manual requirements. `--require-gates` checks only available static scoring targets and must not be interpreted as full release approval.
